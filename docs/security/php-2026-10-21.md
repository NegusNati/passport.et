# PHP security update, October 21, 2026

## Production finding

The safe public API check, performed **before changing PHP configuration**,
reported:

```json
{"patch_status":"vulnerable","php_version":"8.3.33","reason":"PHP 8.3.33","exit_code":1}
```

Target: `https://api.passport.et`.

Checker: [openai/php2shell-checker](https://github.com/openai/php2shell-checker),
commit `0c1945ae07e09160b63cde4e6544160ec99d65e8`.
The URL skill and implementation were reviewed before execution. It reads
HTTP response headers using HEAD (GET only after 405/501), does not follow
redirects, and sends no exploit payloads. All **31 upstream checker tests passed**.
No global skill installation or server-side checker installation was needed.

The [official advisory](https://www.php.net/archive/2026.php#2026-10-21-5)
includes PHP-FPM among affected installations. PHP **8.3.36** fixes:

- CVE-2026-109618, remote code execution via out-of-memory corruption.
- CVE-2026-109619, remote code execution via stale global state.

This is version-based evidence, not proof of successful exploitation or a
compromise assessment. Headers can be overridden, and vendor backports need
server-side package verification. Hidden headers must be reported as **UNKNOWN**,
not patched. This work was limited to the public check; it did not inspect the VPS.

## Repository remediation

- Both PHP images now pin `php:8.3.36-fpm-alpine`, retaining their extensions,
  PDF tools, users, and existing upload/time limits.
- Composer's PHP requirement is `~8.3.36`, with platform `8.3.36`. Only lock
  platform metadata and its Composer-generated content hash changed; package
  versions and source references remain unchanged.
- CI uses PHP 8.3.36, checks actual Composer platform requirements, and has a
  separate job to build both Dockerfiles and verify their CLI/FPM versions.
- Deployment refreshes the pinned PHP base images and verifies both new images
  before dependency installation, then verifies running PHP/Horizon containers.
  The guard requires stable PHP 8.3.36+ within 8.3 and matching CLI/FPM versions.
- Existing shared-VPS isolation is unchanged. No pruning, database upgrades,
  shared-proxy restarts, automatic migrations, or weaker memory limits were added.

Pinning a source file is **not** an update to an already running FPM worker.
Maintenance mode also does not mitigate attacks that happen before application
code. Production must be rebuilt and its workers replaced through an authorized
deployment before this issue can be considered remediated there.

## Validation

- Added security regression checks first and confirmed failures against the old
  floating image tags, old Composer/CI configuration, and missing runtime guard.
- **26 project configuration, deployment, and PHP policy tests passed** after
  the changes, including rejection of stale PHP/Horizon images and containers.
- Composer validation, PHP syntax, and deployment shell syntax passed.
- Docker image verification/build is **blocked** in this environment:
  `auth.docker.io` DNS resolution times out when pulling both the PHP and
  Composer base images. The requested official tag's registry availability
  therefore could not be confirmed.
- The FPM image build was attempted and failed at base-image metadata lookup.
  The worker image needs the same base images, so it and actual runtime/version,
  extension, Composer-platform, and Laravel unit/API/import tests remain
  unverified locally. No existing database or container was repurposed for tests.
- CI now requires these real image checks and the application tests before a
  deployment can proceed. They must pass; do not substitute an older cached image
  or disable platform/security checks.
- ShellCheck is configured in CI but unavailable locally.

The local Homebrew PHP CLI remains 8.5.11, as requested. It is not the application's
Docker runtime and does not validate this patch. Updating it needs a separate
authorized local upgrade.

## Production follow-up

After successful image builds and CI, an operator must authorize deployment.
Only Passport's application containers should be replaced. Afterward, run the
following from the existing production checkout:

```bash
cd ~/laraveldocker.prod
for service in php horizon; do
  sudo docker compose --project-name laraveldockerprod \
    --project-directory "$PWD" --env-file "$PWD/.env" \
    -f "$PWD/docker-compose.prod.yml" \
    exec -T "$service" php scripts/check-php-runtime.php
done
```

Both guards must report matching CLI/FPM versions at least 8.3.36 within the
supported 8.3 branch. Also verify `/up`, passport search, imports/Horizon, and
the other public sites without restarting their containers or the shared proxy.

Repeat the reviewed checker against the public API:

```bash
node "$CHECKER_DIR/skills/phpcheck-url/scripts/phpcheck.js" \
  https://api.passport.et --json
```

`CHECKER_DIR` must refer to the reviewed commit above. A patched response header
is supplementary evidence; if headers are hidden, retain the successful
container/FPM checks rather than assuming UNKNOWN means safe.

No commit, push, deployment, VPS SSH session, or Homebrew upgrade was performed
as part of this repository change.
